# VS-14 — Goals Visual Migration

## Outcome
Migrate the existing authenticated Goals experience to the approved Atlas visual system while preserving FR-04 persistence, Business isolation, and PES Mobile architecture.

## Requirements
- FR-04 — Business Goals

## Acceptance criteria
1. Existing goals load and save through the unchanged authenticated Business API boundary.
2. Existing goals can be reprioritised with contiguous one-based priorities and boundary-safe controls.
3. Custom goals trim owner input and reject empty, case-insensitive duplicate, and over-limit additions before save.
4. Loading, missing-session, starter-default, load-error, ready, validation, saving, save-error, and success states are honest, recoverable, and accessible.
5. The screen uses the approved Atlas visual grammar, `BrandMark`, shared tokens, keyboard-safe scrolling, 44-point actions, dynamic text, and narrow/tablet containment.
6. Authentic Expo runtime evidence covers representative and narrow widths plus reorder, validation, saving, and recovery interactions.
7. Mobile tests, typecheck, lint, governance, slice validation, preflight, CI, Security baseline, and Product Intake pass on the exact certified head.
8. No API, domain, migration, auth, navigation architecture, dependency, release, or production change is introduced.

## Non-goals
- Goal removal or deactivation
- Drag-and-drop ordering
- New generic goal catalogue or analytics
- API, domain, database, auth, navigation, release, or production changes

## Risk and evidence
Risk is medium. Evidence must include pure behavior tests, authentic Expo runtime assertions/screenshots, deterministic PES gates, exact-head remote workflows, and an honest native-device limitation when unavailable.
