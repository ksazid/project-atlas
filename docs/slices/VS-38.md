## Outcome

Give Atlas fresh pilot evidence through one read-only Google Drive folder so Today recommendations can be grounded in normalized operational Signals and Changes without retaining raw files or customer PII.

## Scope

- one Viewer-shared Google Drive Atlas folder per Business;
- manual `Sync now` and scheduled polling through the same idempotent service;
- new/changed CSV detection by Drive file ID, modified metadata, size and content fingerprint;
- CSV preview, validation, normalization, signal persistence and deterministic changes;
- Profile/Business Hub `Business data` card and connector workflow;
- device CSV upload as fallback;
- provider-neutral operational evidence projection into the existing intelligence boundary.

## Security and privacy

- no public-link sharing;
- no whole-Drive OAuth grant or user Google refresh token;
- Viewer-only connector access and no Drive write methods;
- raw bytes/rows are transient and never durably stored or logged;
- customer identity, address, notes and payment-secret fields are ignored or rejected before normalization;
- all commands and records are owner-authorized and Business-isolated;
- connector runtime credentials stay server-side.

## Acceptance

1. A Business owner can connect exactly one eligible folder, see status/freshness, run Sync now and configure the pilot schedule.
2. Scheduled and manual sync produce the same idempotent result.
3. Unchanged files are not reprocessed; changed content is fingerprinted and safely normalized.
4. Atlas leaves raw CSV in Drive and persists no raw content or customer PII.
5. Device upload remains available as a secondary fallback.
6. Normalized Signals and Changes carry provenance and can become existing provider-neutral evidence without weakening no-filler policy.
7. Revoked folder access becomes a truthful reauthorization state.
8. No external action, Drive write, new tab, analytics dashboard, provider webhook, deployment or production enablement is introduced.

## Rollback

Disable scheduled polling and connector commands, retain already-normalized provenance records for audit/history, and leave every raw source file untouched in Google Drive. Database rollback is forward-fix only after any shared environment migration; no destructive production action is authorized in this slice.
