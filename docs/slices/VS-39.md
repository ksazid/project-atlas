# VS-39 — Operational Signal Recommendations

## Outcome

Atlas turns material normalized operational changes from VS-38 into deterministic, goal-aligned Today recommendations using versioned Restaurant & Café Knowledge Pack rules. The existing recommendation ranking, cooldown, snapshot, API and mobile boundaries remain authoritative.

## Acceptance criteria

- Eligible metrics are exactly `gross-sales`, `orders`, `repeat-orders`, and `delivery-time`.
- A relative deterioration of exactly 10% or more qualifies over exactly 7 or 28 days. Sales, order and repeat-order deterioration is a decrease; delivery-time deterioration is an increase.
- A comparison value of zero is ineligible. Positive, unchanged, below-threshold, malformed, unsupported-window and historical evidence produces no candidate.
- Fresh evidence may retain manifest confidence. Stale operational evidence forces Low confidence.
- Thresholds, eligibility, goal mappings, recommendation copy and owner-controlled execution templates are isolated to the Restaurant & Café Knowledge Pack. Provider-neutral infrastructure does not switch on category metrics.
- Every candidate preserves the exact BusinessChange ID and underlying Signal IDs. Evidence remains Business-isolated.
- Copy describes observed association only. It must not claim causation, guarantees, blame, invented customer segments, providers, employees or menu facts.
- When no eligible pattern matches, Atlas emits no operational recommendation; it never manufactures filler.
- Existing goal alignment, deterministic ranking, cooldown, evidence snapshots, API response shapes and mobile routes remain unchanged.

## Rollback

Revert the VS-39 feature commits and restore Restaurant & Café manifest version 1.0. No database rollback or raw-file recovery is required because this slice adds no migration and stores no new connector payload.

## Certification

Certification requires the exact feature-branch head to pass API tests, full CI, Security baseline, Product intake, governance validation and deterministic secret scanning. Certification, release, deployment, EAS/OTA and production enablement require separate explicit approval.

## Exclusions

No migration, dependency, connector change, raw-file storage, customer PII, AI provider, external action, mobile change, deployment or production mutation is in scope.
