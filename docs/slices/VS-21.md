# VS-21 — Business Location Resolution Remediation

## Purpose

Remediate defects exposed while validating VS-16 URL-first discovery on the isolated Expo Go test harness. Preserve the approved Atlas onboarding design while making business/branch location selection canonical and owner-friendly.

## Requirements

- FR-02 Business creation.
- FR-03 Business Profile.
- FR-16 degraded/insufficient-context states.

## Scope

- Fix marketplace merchant identity fallback when provider metadata is generic.
- Resolve an operating location through a provider-neutral server-side boundary.
- One strong location: preselect, owner can change.
- Multiple locations: owner selects the branch being set up.
- Unknown location: `Find your business location` via Google Places when configured.
- Derive country, IANA timezone and ISO currency from the selected location.
- Remove technical country/timezone/currency text entry from discovery onboarding.
- Surface field-level validation errors.
- Preserve provenance, owner confirmation and SSRF protections.

## Out of scope

Production release/enablement, bulk multi-branch onboarding, private marketplace/POS connectors, cross-location intelligence aggregation, and navigation/visual redesign.

## Acceptance criteria

- Bolt/Wolt merchant pages do not become generic provider names when a merchant slug/name is available.
- One candidate is preselected but changeable.
- Multiple candidates require explicit branch selection.
- No candidate exposes Google location search rather than ISO/IANA text fields.
- Selected location supplies canonical country/timezone/currency.
- Server remains authoritative and mobile shows actionable validation details.
- Test, security and governance gates pass before any merge discussion.
