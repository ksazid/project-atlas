# VS-30 — Today’s Focus Evidence Compatibility Repair

## Status

Approved corrective runtime slice executed before VS-29 runtime work.

## Requirements

Implements and repairs **FR-07 — Today’s Focus** and the honest degraded/no-focus behavior in **FR-16**.

## Problem

A Restaurant & Café Business can persist owner-confirmed operating channels under the canonical onboarding key `operatingchannels`, while the Opportunity generator recognises older ordering-channel aliases such as `primarychannels`. This integration mismatch can make a real category-specific evidence path invisible.

The Generic Business fallback can also qualify from profile + goal policy checks alone. Because those checks are interpretation/policy inputs rather than factual evidence, the resulting Opportunity can be persisted with `0 evidence items`, contradicting FR-07 eligibility and the product principle to never create filler recommendations.

## In scope

- reproduce the regression with deterministic tests;
- make the Opportunity generator recognise the canonical confirmed `operatingchannels` context key without rewriting stored Business Context;
- require at least one non-policy factual evidence item before any generated candidate is eligible for Today’s Focus;
- preserve category-specific ranking, provenance, exact Knowledge Pack versions, owner control and existing confidence policy;
- verify a revenue/growth Restaurant & Café case with confirmed operating channels selects the category-specific ordering-path recommendation;
- verify profile + goal alone does not generate a zero-evidence fallback Opportunity;
- update traceability/evidence and run repository gates.

## Out of scope

- new recommendation categories or AI generation;
- changes to Goals, onboarding enrichment, labels or VS-29 scope;
- changes to stored Business Context keys or migrations;
- navigation/UI redesign;
- deployment, release, production enablement or production database mutation.

## Acceptance criteria

1. A confirmed Restaurant & Café Business with a growth/revenue goal and owner-confirmed `operatingchannels` can generate the existing `ordering-path-clarity-review` candidate.
2. The selected Opportunity includes at least one factual evidence item and never reports `0 evidence items`.
3. Profile + goal policy evidence by itself cannot qualify a candidate for Today’s Focus.
4. Existing category-specific evidence keys and legacy `primarychannels` compatibility continue to work.
5. No persistence migration or production data rewrite is required.
6. Deterministic API tests and repository preflight pass before certification.

## Governance boundary

This is a bounded corrective slice restoring already-approved FR-07 behavior. It introduces no new provider, retention, sensitive-data, external-action, deployment or release policy. VS-29 remains specification-only until this repair is merged and its branch is refreshed from the resulting `main`.
