# VS-36 — Menu & Media Coverage Recovery

## Purpose
Close the deferred public menu/media coverage gap inside approved Atlas v1.0 discovery and Business Profile scope without adding a new provider, storage model or scraping subsystem.

## Base
Fresh post-VS-35 main: `ff4ca1ac2245ef8f29f4efc5d04693d99f7ec597`.

## Authority
- PRD FR-02, FR-03, FR-05
- TRD public-data adapter, provenance, safe-degradation and provider-neutrality requirements
- DESIGN v1.2 degraded-state and trust requirements
- PES/Loop governance
- DEC-04 and DEC-07

## Scope
- preserve certified JSON-LD and Bolt semantic menu/media extraction;
- add explicit provider-neutral media/menu coverage classification;
- distinguish renderer-dependent supported provider pages from true absence of parseable media/menu evidence;
- recover graph-linked schema.org Menu/MenuSection/MenuItem structures;
- retain safe remote MenuItem image references with complete public-source provenance;
- propagate renderer-required coverage through the existing discovery-source warning/provenance boundary;
- preserve reconciliation so mismatched/ambiguous source media/menu remains excluded;
- preserve existing Business media/offering materialisation and owner-confirmation semantics.

## Safety boundary
Atlas only accepts data contained in the already-authorised fetched public HTML response. VS-36 does not use private/undocumented provider APIs, crawler impersonation, search-engine/cache content, JavaScript execution or production headless-browser scraping. Third-party image binaries are never copied or rehosted.

## Embedded-state boundary
No generic embedded-state heuristic is authorised. A provider-specific embedded public-state parser may be added only after a current raw public-document fixture proves a stable parseable shape and a deterministic RED test is committed first. If no such raw shape is reproduced, renderer-required classification is the intended behavior.

## Persistence
Use existing `BusinessDiscoverySource.WarningCode` for renderer-required provenance when applicable. Do not create a Business fact for coverage and do not add a database migration solely for this diagnostic.

## Owner boundary
No new owner screen, tab or workflow is required. Business Hub and full-menu views continue to render only persisted provenance-backed media/offering data. Today / History / Goals / Profile and Pilot Operations remain unchanged.

## Out of scope
- private Bolt/Wolt APIs or POS/menu-provider connectors;
- production browser automation or crawler impersonation;
- search-index/cache snippets as evidence;
- copied media binaries;
- ordering, inventory, price history or competitor intelligence;
- speculative parsing of unknown provider state;
- new database migration solely for coverage diagnostics;
- deployment, release, EAS/OTA or production database mutation.

## Success
Atlas preserves current VS-25 behavior, recovers additional standards-based public menu/media where deterministically available, records renderer-dependent coverage truthfully through existing provenance, and never converts an unobservable menu into a false “no menu” claim.
