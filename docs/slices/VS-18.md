# VS-18 — Knowledge Pack Schema v2

## Requirement traceability

- FR-06 — Knowledge Pack support
- Technical authority: ATLAS-TRD-001 Knowledge Pack contract

## Objective

Introduce the deterministic backend-packaged Manifest Schema v2 that Atlas Category Intelligence can consume while retaining the current v1 persistence and exact-version assignment model.

## Acceptance criteria

1. Schema version is exactly `2`.
2. Manifest identity retains pack key, exact version and layer.
3. Layers are bounded to Core, Category, Subcategory and Local/Market.
4. Category/subcategory applicability uses the canonical Atlas taxonomy.
5. KPI definitions, evidence rules, Opportunity patterns, execution templates, measurement suggestions, seasonality and guardrails are typed and bounded.
6. Stable keys are unique within each section.
7. Opportunity-pattern references to evidence rules and execution templates are validated.
8. Core manifests cannot claim category specificity.
9. Category manifests must target at least one known category.
10. A deterministic SHA-256 fingerprint can be reproduced from the same semantic manifest.
11. The built-in Generic Business Core v2 manifest is industry-agnostic.
12. No database migration, dynamic remote pack installation, private connector, provider commitment, release or deployment is introduced.

## Implementation mode

`runtime-enabled` for packaged contract code used by subsequent runtime slices. There is no new customer-facing route in VS-18.

## Risk

Medium: this becomes an intelligence contract consumed by future opportunity generation, but does not itself change persistence or external behavior.

The Product Owner approved the next five Atlas slices on 2026-08-10 and instructed implementation, fixes, certification and merge after required gates pass. This slice is the first of those five. Release and production enablement remain unauthorized.
