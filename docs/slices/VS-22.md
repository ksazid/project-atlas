# VS-22 — Multi-Source Business Discovery & Fact Reconciliation

## Purpose

Extend the existing URL-first Business discovery flow so an owner may use one primary public Business page and up to two optional secondary public sources without weakening Atlas security, provenance, owner control or the VS-21 canonical location boundary.

## Requirements

- FR-02 Business creation.
- FR-03 Business Profile.
- FR-05 Business Context/public data.
- FR-16 empty and degraded states.

## Approved scope

- One primary discovery URL is shown initially.
- The in-field `+` adds up to two optional additional URL rows.
- Every populated row has a one-tap `×` clear/remove action.
- Complete pasted URLs are immediately canonicalised in the visible input; surrounding share text and tracking contamination are removed only when one unambiguous HTTPS URL can be identified.
- Server-side canonicalisation and validation repeat authoritatively before any external request.
- Bolt Food and Wolt are accepted only for routes identifying one specific Business/venue.
- Google Maps/place share links are accepted through a controlled Google-only redirect resolver and the existing Google Places boundary; generic Google Search URLs are rejected as authoritative Business sources.
- All outbound page fetching retains strict SSRF controls, bounded time/content reads and no arbitrary redirects/browser execution.
- Primary source order is owner-authoritative. Secondary sources fill only missing fields, equivalent facts corroborate, conflicts retain the higher-priority value and unrelated/ambiguous sources cannot silently contaminate the selected Business.
- Actual source/provider provenance remains persisted internally while owner-facing copy remains provider-neutral.
- Location, country, timezone and currency remain resolved through the VS-21 canonical location flow.
- A large page may succeed when useful metadata occurs within Atlas's fixed safe read prefix; total remote response size alone is not a reason to reject it.
- `Confirm and continue` must consume a valid reconciled snapshot without a server 5xx.

## Security policy

All three URL rows use the same syntactic/provider policy. The API additionally enforces network policy before connect and on the connected address: HTTPS only, standard port, no credentials, no IP literals, no localhost/internal/test/local destinations, no private/link-local/reserved/documentation/multicast address classes, no proxy routing, no cookies/authentication to sources, no script execution, bounded request/read/parser work and provider secrets remaining server-side.

`maps.app.goo.gl` is the only redirecting source type in VS-22. Redirects are manual, Google-host allowlisted, HTTPS-only, DNS/connect validated at every hop and capped at four hops. Ordinary websites, Bolt and Wolt do not gain automatic redirects.

## Reconciliation rule

For every supported fact key:

1. Select the first usable value in owner-defined source order.
2. A later equivalent value becomes corroborating evidence only.
3. A later differing value is retained as conflict evidence and does not overwrite automatically.
4. A source that cannot be associated confidently with the same Business is excluded from selected reconciliation.
5. Never fabricate a merged value.

## Out of scope

More than three URLs, whole-site crawling, authenticated/private source access, social-network scraping, arbitrary redirect following, browser automation, autonomous conflict resolution, review-content ingestion as authoritative owner facts, deployment-branch work and production deployment.

## Acceptance criteria

- One source works exactly as before, subject to the stricter canonicalisation policy.
- Up to two optional secondary sources may be added and removed accessibly.
- Bolt/Wolt/Google share contamination is removed from the visible URL before discovery when safely canonicalisable.
- Unsafe, generic, duplicate or ambiguous URLs are blocked before fetching.
- A Google Maps specific-place link is resolved through Google Places, not scraped as HTML.
- Secondary sources fill missing facts without duplicating or overwriting higher-priority facts.
- Source conflicts/mismatches are retained and surfaced truthfully rather than silently merged.
- Source/evidence provenance is auditable and legacy single-source snapshots remain readable.
- Large Wolt-style pages are bounded safely rather than rejected solely for total size.
- Valid confirmation completes without 5xx.
- API/mobile/migration/security/governance/exact-head CI gates pass before merge discussion.
- No deployment is performed as part of VS-22 implementation or merge readiness.
