## Approved scope

- harden provider/public media and menu extraction;
- extract normalized public website, business phone, public business email, social channels and opening-hours evidence;
- allow one bounded, strongly matched official-site enrichment hop under existing SSRF/public-source controls;
- preserve Google Place enrichment as transient review-time data under DEC-08;
- persist canonical operating/profile values only through explicit owner confirmation;
- suppress redundant progressive onboarding questions deterministically when equivalent confirmed context already satisfies them;
- provide a Development/Expo-demo-only reset-and-switch-business flow while preserving the production one-primary-Business-per-owner invariant;

- production ownership-rule changes;
- new persistence schema or migration unless separately routed through PES;
- production deployment, EAS build/submit/OTA, release or production database mutation.

## Current Google Places policy review — 2026-08-12

Implementation-time review of current official Google Maps Platform documentation confirms:

- Place Details (New) requires an explicit field mask; phone, opening-hours and website fields remain available but are billed at higher Place Details tiers.
- Google Places content generally must not be prefetched, cached or stored outside documented exceptions; Place IDs remain the durable storage exception.
- EEA billing accounts are subject to separate Places API permitted-use restrictions.

VS-29 therefore does **not** expand durable Google-derived business intelligence. Existing DEC-08 remains controlling: Google rich Place content stays transient in the current owner interaction, Atlas retains only permitted provider references such as Place ID, and canonical durable values are created only through explicit owner confirmation. New durable contact/presence enrichment should come from already-approved public/official-site sources. No new Google contact/presence field-mask expansion is required for VS-29 unless separately cleared against the applicable EEA permitted-use category.

Official references reviewed:

- Google Places API Place Details (New)
- Google Places API policies and attribution requirements
- Google Place ID storage guidance
- Google Maps Platform EEA Places API permitted uses

## Acceptance boundary

VS-29 passes only when deterministic tests demonstrate that:

1. structured and visible public business evidence normalizes into the existing provenance-rich discovery model;
2. duplicate/malformed/unsupported public contact and social data is rejected conservatively;
3. official-site enrichment is bounded, strongly identity-matched and SSRF-safe;
4. provider/media/menu regressions remain fixed for the approved representative page shapes;
5. owner-confirmed values are never silently overwritten;
6. opening-hours and equivalent canonical values persist only through explicit confirmation;
7. redundant onboarding questions are semantically suppressed without hiding genuinely missing context;
8. Development/Expo-demo reset can switch businesses safely while production retains the one-primary-Business rule;
9. VS-28 native shell and VS-30 Today’s Focus evidence behavior remain intact;
10. repository preflight, mobile/API tests, security and product-intake gates pass on the exact final SHA.
