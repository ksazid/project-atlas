# VS-17 — Progressive Business Questions

## Purpose

Add an optional, resumable intelligence-enrichment step immediately after Business creation. Atlas asks only the highest-value missing business-context questions, one at a time, and the owner may answer or skip every question before continuing to Today.

## Requirements

- FR-03 — Business Profile / useful business context
- FR-05 — Business Context, owner confirmation, and data minimisation
- Locked Category Intelligence Foundation direction
- ATLAS-DESIGN-001 v1.2
- Approved VS-17 design: `docs/superpowers/specs/2026-08-10-vs-17-progressive-business-questions-design.md`

## Acceptance criteria

1. VS-17 starts only after a Business has been successfully created by the existing URL-first or manual flow.
2. The server owns an immutable/versioned `progressive-onboarding` question catalogue; no LLM/model call generates or ranks onboarding questions.
3. Selection is deterministic and category-aware, using Generic Business plus lightweight coverage for Restaurant & Cafe, Beauty & Personal Care, Retail, Ecommerce, Home & Local Services, Professional Services, Fitness & Wellness, and Hospitality / Accommodation.
4. Atlas suppresses questions whose target context is already reliably known from owner-confirmed/canonical data or previous VS-17 answers.
5. First-run enrichment returns at most five questions and normally 3–5 when that many useful unknowns exist; if fewer useful questions exist, Atlas returns fewer and never adds filler.
6. Every question is skippable. A skip records progress only and never creates an empty/fake Business Context value.
7. Answered questions persist through the existing `BusinessContextEntry` as owner-sourced and owner-confirmed; authoritative answers are not duplicated into a second facts table.
8. Question progress persists separately with Business, catalogue key/version, question key, answered/skipped status, optional answered context key, and completion timestamp.
9. A catalogue version change alone never causes a previously skipped question to be re-asked. Future re-asking requires a separately implemented material-value trigger and is outside VS-17.
10. API list/answer/skip operations are Business-owner isolated, reject arbitrary/stale catalogue/question inputs safely, validate bounded answers, and behave stably under duplicate submissions.
11. Mobile UX is one-question-at-a-time, tap-first, with explicit progress, `Skip for now`, concise helper copy, and short free text only where bounded choices are insufficient.
12. Business creation routes into VS-17; app resume re-enters VS-17 only when eligible questions remain. If optional enrichment is unavailable/offline, the owner can continue to the existing Today journey and is never trapped.
13. Loading, zero-question, saving, validation, save-failure/draft-preservation, stale refresh, skip, completion, retry, and `Continue for now` degraded states are covered.
14. Accessibility includes semantic headings, selected/unselected semantics, non-colour state, reduced-motion-safe behavior, keyboard-safe text input, dynamic-type-safe copy, >=44pt enabled targets, and no phone/tablet horizontal overflow.
15. The combined fast-onboarding journey continues to target roughly 60–90 seconds when VS-16 enrichment succeeds and tap-first answers are used.
16. Exact-head CI includes deterministic catalogue/API/mobile tests, authentic Expo Web phone/tablet runtime evidence, clean PostgreSQL migration, .NET build/tests, Security baseline, and Product Intake.
17. Release, deployment, OTA publishing, EAS publishing, infrastructure changes, and production enablement remain unauthorized.

## Out of scope

- AI-authored onboarding questions;
- Knowledge Pack Schema v2;
- Restaurant/Cafe metric engine, diagnostics, opportunity recipes, or first category-aware Opportunity;
- recommendation-triggered re-asking of skipped questions;
- private Wolt/Bolt/POS/reservation/accounting connectors;
- long mandatory questionnaires;
- navigation redesign;
- release/deployment/production enablement.
