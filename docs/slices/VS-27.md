# VS-27 — Business Hub & Atlas Brand Experience

## Outcome

Give Business owners a read-first Business Hub that presents the Business Atlas understands: identity, operating facts, bounded persisted imagery, compact menu intelligence and context status, while keeping editing behind an explicit secondary action.

## Authority

- `ATLAS-PRD-001` — FR-03, FR-05, FR-16
- `ATLAS-TRD-001`
- `ATLAS-DESIGN-001` v1.2
- merged VS-25 baseline `170ff58125b6efcf299191117d01f09dd0270896`
- merged/certified VS-26 baseline `7c07d0f94cef157484d91ff7710460a6f0f4e49a`
- approved design: `docs/superpowers/specs/2026-08-11-vs-27-business-hub-atlas-brand-experience-design.md`
- approved implementation plan: `docs/superpowers/plans/2026-08-11-vs-27-business-hub-atlas-brand-experience.md`

## In scope

- account-isolated Business Hub read API over existing persisted Business/Profile/Media/Offering/Context records;
- read-first Business tab;
- persisted Business Media Reference preview;
- compact menu intelligence summary and dedicated read-only full menu screen;
- existing Business Profile editor retained behind `Edit business details`;
- Atlas-owned local Compass Orbit brandmark replacing the remote Starbucks prototype asset;
- coherent local five-tab icon family while preserving route names and PES navigation structure;
- truthful loading, empty, degraded and retry states.

## Out of scope

- new provider fetches or new provider-data persistence;
- database migration solely for this UI slice;
- menu editing, ordering, cart, checkout, POS sync or availability management;
- media upload, binary copying or rehosting;
- Today Focus readiness/recommendation changes;
- VS-26 onboarding, Goals or Context logic redesign;
- PES navigation restructuring;
- Starbucks logo, siren, crown, stars, cup artwork, trade dress or remote Starbucks assets;
- production release, deployment, EAS build/submit or OTA.

## Conflict boundary

VS-27 starts from merged VS-26 `main`. The post-merge overlap review found only `apps/api/Program.cs` among planned VS-27 runtime files was modified by VS-26. VS-27 must add endpoint wiring to the current post-VS-26 Program without reverting Place enrichment or onboarding changes. Business Hub/Profile/nav/BrandMark surfaces are otherwise isolated from VS-26 runtime changes.

## Acceptance

- no Starbucks runtime asset/reference remains in the mobile BrandMark implementation;
- Business Hub renders persisted media/menu intelligence when present and honest empty states otherwise;
- Business Hub and full-menu reads are Business-owner isolated and return safe not-found semantics for another owner;
- media preview is bounded and only valid HTTPS references are rendered;
- menu preview is compact; full menu remains read-only intelligence rather than an ordering experience;
- existing profile save behavior remains available behind the edit route;
- five tab route names remain `index`, `profile`, `goals`, `context`, `settings`;
- touch targets, labels, dynamic text and degraded states remain accessible;
- API/mobile deterministic tests and repository preflight pass;
- Expo Go runtime acceptance is completed before certification;
- no production release or enablement occurs without separate exact-SHA approval.
