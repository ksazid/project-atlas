# VS-03 — Knowledge Pack Foundation

## Status

Approved implementation slice after VS-02. This slice establishes the Business Domain foundation for future AI capabilities without implementing AI execution.

## Locked architecture

- PES Mobile navigation, routing, authentication, state management, folder conventions, design system, API-client architecture and framework structure remain unchanged.
- Knowledge Pack is a Business Domain feature, not a PES framework capability.
- Internal persistence is modular: `KnowledgePack -> KnowledgePackVersion -> KnowledgeSection[]`.
- Users experience one cohesive Knowledge Pack; internal section and storage mechanics remain hidden.
- Published versions are immutable. Editing a published version creates a new draft.
- Businesses reference an exact published `KnowledgePackVersion`; publishing a newer version never changes an assignment automatically.
- The model is retrieval-friendly, locale-ready and future-embedding-compatible, but VS-03 adds no AI provider, embeddings or vector database.

## Version lifecycle

`Draft -> Review -> Published -> Archived`

Permitted correction path: `Review -> Draft`.

Invalid transitions are rejected. Published and archived versions are immutable. Publication requires valid content and at least one section.

## Domain model

### KnowledgePack

Stable pack identity, key, name, description, archive state, creator, timestamps and optimistic concurrency.

### KnowledgePackVersion

Exact version number, lifecycle status, locale, creator/reviewer/publisher metadata, timestamps and optimistic concurrency.

### KnowledgeSection

Stable ID and logical key, category, title, structured content, metadata, ordering, locale, translation group, provenance and optimistic concurrency.

Supported initial categories include Business Overview, Services, FAQs, Brand Voice, Policies, Pricing, Promotions, Sales Guidance, SOPs and Custom.

### BusinessKnowledgeAssignment

Business, pack and exact version references; retained key/version; current/effective state; actor and timestamps; assignment history and optimistic concurrency.

## Backend scope

- pack CRUD and archive controls;
- draft/version creation and history;
- section CRUD and ordering for editable versions;
- review, publish and archive transitions;
- new draft creation from a published version;
- version comparison;
- explicit assignment and assignment history;
- effective-version resolution;
- audit trail, authorization, safe errors and Business isolation.

## Mobile scope

Add a Knowledge Pack screen, cohesive section viewer, meaningful version/status indicator, loading/empty/unavailable/retry states, refresh handling and offline cache without changing PES framework architecture.

## Admin scope

Provide pack list/details, section editor, ordering, version history, draft/review/publish/archive workflow, assignment management/history, comparison, validation and concurrency feedback through existing authorization patterns.

## Documentation

Keep synchronized: `README.md`, `docs/architecture.md`, `docs/domain-model.md`, `docs/roadmap.md`, `docs/changelog.md`, `docs/decisions.md` and this slice specification.

## Backward compatibility

No breaking PES, API, authentication, navigation, routing or state-management changes. Use incremental EF Core migrations only. VS-01 and VS-02 behavior and Business isolation must continue working.

## Runtime and safety boundaries

Runtime remains disabled outside development/test. No deployment, release, production credentials, paid third-party service, AI provider, embedding or vector infrastructure is authorized.

## Future consumers — not implemented here

- VS-05 AI Context Engine
- VS-06 Conversation Engine
- VS-07 Prompt Studio

They must be able to consume the effective assigned version, ordered locale-aware sections, stable IDs, metadata and historical exact-version references without redesigning VS-03.

## Acceptance criteria

1. PES framework structure is unchanged.
2. Modular pack/version/section persistence is implemented.
3. Published versions and sections are immutable.
4. Editing published content creates a new draft.
5. Every enabled Business resolves one exact published version.
6. New publication never automatically replaces an assignment.
7. Cross-Business access returns safe not-found responses.
8. Lifecycle, assignment and mutation commands are authorized, audited and concurrency-protected.
9. Incremental migration and regression tests preserve VS-01 and VS-02.
10. Mobile presents one cohesive Knowledge Pack.
11. Required documentation and architecture decisions remain synchronized.
12. No AI runtime, embeddings, vector database, deployment or production enablement is introduced.
