# VS-03 — Knowledge Pack Foundation

## Status

Implementation is substantially complete in draft PR #7. Certification is pending because GitHub Actions has not created workflow runs for the branch.

This slice establishes the Business Domain foundation for future AI capabilities without implementing AI execution.

## Locked architecture

- PES Mobile navigation, routing, authentication, state management, folder conventions, design system, API-client architecture and framework structure remain unchanged.
- Knowledge Pack is a Business Domain feature, not a PES framework capability.
- Internal persistence is modular: `KnowledgePack -> KnowledgePackVersion -> KnowledgeSection[]`.
- Users experience one cohesive Knowledge Pack; internal section and storage mechanics remain hidden.
- Published versions are immutable. Editing a published version creates a new draft.
- Businesses reference an exact published `KnowledgePackVersion`; publishing a newer version never changes an assignment automatically.
- The model is retrieval-friendly, locale-ready and future-embedding-compatible, but VS-03 adds no AI provider, embeddings or vector database.

## Implemented domain model

- `KnowledgePack`
- `KnowledgePackVersion`
- `KnowledgeSection`
- `BusinessKnowledgeAssignment`

The migration is incremental and includes foreign keys, unique pack/version and section constraints, optimistic concurrency, and a filtered unique index that permits many historical assignments but only one current assignment per business.

## Version lifecycle

`Draft -> Review -> Published -> Archived`

Permitted correction path: `Review -> Draft`.

Invalid transitions are rejected. Published and archived versions are immutable. Publication requires at least one section.

## Implemented backend

- pack creation and listing;
- draft-version creation;
- draft creation from a published version;
- section create, update, delete and ordering;
- review, publish and archive transitions;
- explicit business assignment to a published version;
- effective-version resolution and assignment history;
- version comparison for added, removed, changed and reordered sections;
- business-owner read APIs;
- internal-operator management APIs;
- audit records, authorization, safe not-found behavior and optimistic-concurrency feedback.

## Implemented mobile experience

- unified Knowledge Pack presentation through the existing Home route;
- ordered section viewer;
- version indicator;
- loading, missing-business, unavailable, retry and empty-content states;
- pull-to-refresh;
- secure offline cache and stale-copy indication;
- accessibility roles and live status messages.

No tab, route, navigation, authentication, state-management or framework restructuring was introduced.

## Admin status
