# VS-09 — History

## Requirement

Implements approved PRD requirement **FR-12 — History**.

## Scope

Atlas exposes a chronological, business-isolated History of prior Opportunities and owner Actions without duplicating or rewriting historical domain records.

History includes, where available:

- Opportunity title, category/context and goal alignment
- Action status and structured decision reason
- Execution Kit availability and usage summary
- owner feedback/usefulness already captured by approved slices
- Outcome summary and evidence classification
- expiry and relevant timestamps
- exact Knowledge Pack key/version provenance
- concise learning summary derived only from recorded facts

## Filters

The MVP History query supports:

- status
- category/source category where recorded
- goal
- from/to date

Filters are optional and composable. Unknown or unsupported values must not broaden access or bypass Business isolation.

## Read model

History is a read-oriented projection over existing VS-04 through VS-08 records. It must not create a parallel source of truth. Historical Opportunity, Action Decision, Execution Kit and Outcome records remain authoritative.

The API may assemble the History response at query time. A dedicated denormalized persistence model is not introduced unless performance evidence later requires one.

## Authorization and privacy

- Business Owner authorization is required.
- Every query is scoped by Business before any filtering.
- Cross-Business identifiers return safe not-found/empty behavior according to existing API conventions.
- No new sensitive customer data is introduced.

## Mobile

Provide a narrative-first chronological History experience with filter controls and clear empty/error states. The user can open the existing Opportunity Detail / Execution Kit journeys from a History item when those resources remain available.

PES framework navigation, routing, authentication, state management, folder conventions and design-system architecture remain unchanged. Business feature routes/components may be added within the existing framework conventions.

## Explicitly out of scope

- Weekly Review generation (VS-10)
- notifications (VS-11)
- pilot admin tooling (VS-12)
- causal attribution or ROI guarantees
- autonomous rewriting of Business Memory
- new analytics warehouse or event platform
- deployment or production enablement

## Acceptance criteria

1. The owner can view chronological Opportunities, Actions, statuses, Execution Kits, feedback and Outcomes where available.
2. History supports status, category, goal and date filters.
3. Results are strictly Business-isolated.
4. Exact historical Knowledge Pack provenance is retained.
5. History is read-oriented and does not mutate authoritative domain records.
6. Empty, filtered-empty, loading and recoverable-error states are clear and accessible.
7. Existing VS-01 through VS-08 behavior remains backward compatible.
8. PES framework structure remains unchanged.
9. API tests/mobile checks/CI/Security/Product Intake pass before certification.
10. Runtime remains development/test only; no deployment occurs in this slice.
