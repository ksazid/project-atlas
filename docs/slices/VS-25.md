## Goal

Extend provider-neutral public business discovery so Atlas can retain useful business imagery references and structured menu/catalogue facts when public sources expose them, without copying third-party image binaries or weakening provenance, privacy or source-safety boundaries.

## In scope

- provider-neutral public media references with canonical remote URL, media kind, source/provider, source page, observed time, confidence and provenance;
- bounded extraction of public business images from structured data and safe OpenGraph fallbacks;
- provider-neutral structured offerings with `menu-item` as the first supported offering kind, including section, name, description, price and currency when publicly observable;
- extraction of schema.org `MenuSection` / `MenuItem` structures and menu-source URLs when available;
- bounded fail-closed extraction from stable public semantic marketplace HTML when the already-supported provider exposes menu facts directly in the same public page;
- multi-source acceptance only from sources already reconciled to the same Business;
- canonical deduplication and strict bounded collection limits;
- persistence on the discovery snapshot before confirmation;
- materialisation to Business-owned media/offerings after owner confirms the Business;
- migration, tenant-isolation, provenance, extraction and persistence tests;
- test deployment only after deterministic gates are green.

## Policy boundary

- Atlas stores third-party **remote references and factual metadata**, not copied third-party image binaries.
- Atlas does not bypass authentication, private APIs, paywalls, bot controls or source access restrictions.
- Public media URLs must pass the existing HTTPS/public-address safety boundary before being retained.
- Provider-specific semantic markup adapters operate only on the same public HTML already accepted by the discovery boundary and fail closed when expected markers are absent.
- No production browser automation is introduced by this slice.
- Owner-uploaded/licensed binary media remains outside this slice and continues to be protected by the repository upload boundary.
- Public menu facts are retained as observations with source/provenance and are not represented as owner-confirmed unless the owner explicitly confirms them later.

## Generic-core rule

Atlas Core must not become restaurant-specific. Persisted commercial items use a generic Business Offering model with `menu-item` as the initial kind; media uses a generic Business Media Reference model. Restaurant/Café Knowledge Packs may interpret those facts later without changing the core persistence contract.

## Bounded limits

- up to 24 retained media references per source observation;
- up to 250 retained structured/public-semantic offerings per source observation;
- media URLs remain HTTPS and at most 2,000 characters;
- offering names/descriptions/sections remain bounded and prices must parse as non-negative decimal values before structured persistence;
- duplicate media URLs and duplicate offering signatures are collapsed deterministically.

## Out of scope

- downloading/rehosting third-party images;
- owner media upload/storage;
- OCR of menu images/PDFs;
- private marketplace/POS APIs;
- automated catalogue editing;
- image/video generation;
- production browser automation;
- production deployment;
- redesign of approved mobile screens.

## Acceptance

1. A public page with valid structured/OG imagery produces bounded, deduplicated media references with complete provenance.
2. A public Restaurant/Menu schema produces structured `menu-item` offerings with section/name/description/price/currency where present.
3. An already-supported marketplace may produce the same bounded offering facts from stable public semantic HTML without private API access; missing semantic markers fail closed.
4. Public menu URLs are retained even when item-level structured data is unavailable.
5. Mismatched/ambiguous secondary sources cannot contribute media or menu data to the selected Business.
6. Discovery persistence survives the discovery → confirmation transaction and materialises accepted records against the created Business.
7. Third-party binary image content is never fetched or stored by this slice.
8. Existing discovery facts, location resolution, Expo Go onboarding and Today flows remain regression-green.
9. CI, Security baseline and Product intake pass at the exact implementation head.
10. No production release/deployment occurs.
