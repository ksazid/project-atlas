# VS-07 — Action Status and Feedback

## Requirement

Implements approved PRD requirement **FR-10 — Action decisions**.

The owner can record **Applied**, **Completed**, **Skipped**, **Not Relevant**, or **Rejected**, with structured reasons where relevant.

## Scope

- Persist an append-oriented Action decision history for a Business Opportunity.
- Expose the current effective Action status and decision history through business-isolated APIs.
- Permit only governed transitions from the existing Opportunity/Execution Kit flow.
- Require structured reason codes and optional owner notes for Skip, Not Relevant and Reject decisions.
- Record actor, timestamp, Opportunity version/provenance and audit metadata.
- Protect against stale writes with optimistic concurrency/version checks.
- Surface the current Action status in Opportunity Detail and Execution Kit mobile experiences.
- Provide accessible owner controls for Apply, Complete, Skip, Not Relevant and Reject as appropriate to the current state.
- Preserve historical decisions; never overwrite prior decision records.

## Status model

```text
Available
  -> Applied
  -> Completed

Available | Applied
  -> Skipped
  -> NotRelevant
  -> Rejected
```

Completed, Skipped, NotRelevant and Rejected are terminal for the recorded Action instance. A future Opportunity may be generated separately; VS-07 does not silently reopen a terminal Action.

## Structured reasons

Skip, Not Relevant and Reject require a reason code. Initial generic codes remain industry-neutral, for example:

- timing-not-right
- already-done
- insufficient-capacity
- not-a-priority
- context-incorrect
- recommendation-not-relevant
- unsafe-or-inappropriate
- other

When `other` is selected, an owner note is required.

## API and persistence

- Business-isolated endpoints only.
- Append-only Action decision records.
- Current status resolved deterministically from ordered decisions.
- Exact Business, Opportunity, Goal and Knowledge Pack provenance retained.
- Optimistic concurrency/stale-version rejection.
- Audit record for every accepted decision.

## Mobile

Extend existing Opportunity Detail and Execution Kit feature modules only. Do not restructure PES navigation, routing, authentication, state management, design system, API client architecture or folder conventions.

The owner must always understand the current status and available next decision. Terminal states are clearly labelled and do not present invalid actions.

## Explicitly out of scope

- Outcome/result capture (VS-08).
- Business Memory learning updates beyond retaining decision history (VS-08).
- History browser (VS-09).
- Weekly Review (VS-10).
- Autonomous publishing, sending or external execution.
- Production deployment or production enablement.

## Acceptance criteria

1. Applied, Completed, Skipped, Not Relevant and Rejected decisions are persisted and auditable.
2. Invalid or stale transitions are rejected deterministically.
3. Reasons are mandatory where specified and `other` requires a note.
4. A Business cannot read or mutate another Business's decisions.
5. Current status is exposed consistently in Opportunity Detail and Execution Kit APIs/UI.
6. Terminal decisions cannot be overwritten or silently reopened.
7. Existing VS-04/05/06 behaviour remains backward compatible.
8. PES framework structure remains unchanged.
9. CI, security baseline, migration and policy tests pass before certification.
10. Runtime remains development/test only; no deployment is performed as part of this slice.
