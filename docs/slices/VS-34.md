# VS-34 — Today Clarity & Navigation Consistency

## Status

**Approved for implementation.**

Product Owner approved the written VS-34 Superpowers design and explicitly authorized Superpowers + TDD implementation through deterministic PES gates. No deployment is authorized.

## Requirements

- FR-07 — Today’s Focus
- FR-10 — Action decisions
- FR-16 — Empty and degraded states

## Goal

Make Today understandable in a few seconds by presenting one obvious daily task, one concise reason, one compact evidence-strength row and one dominant action, while correcting the inconsistent pushed-screen Profile back treatment.

## Approved runtime scope

- change Today ready-state orientation copy to `1 thing worth doing today`;
- present semantic label `BEST MOVE`;
- use strong sans-serif task typography for the recommendation while retaining serif page-title treatment;
- collapse Impact / Effort / Confidence into one compact evidence row using only existing server-provided values;
- primary action copy `I’ll do this` with existing Apply semantics;
- secondary action copy `Why this?` opening Opportunity Detail;
- expose `Later` and `Not relevant` behind a one-tap overflow control while keeping both within two taps;
- remove the duplicate `Want the reasoning?` supporting card;
- preserve native pull-to-refresh, freshness state, safe degraded states and no-filler policy;
- replace the custom Profile text `headerLeft` on Settings, Context and Feedback with the native/light Atlas back treatment, preserving a green fallback route to Profile when no native back stack exists.

## Runtime boundary

Expected runtime changes are limited to:

- `apps/mobile/src/features/today-focus/TodayFocusScreen.tsx`
- `apps/mobile/app/settings.tsx`
- `apps/mobile/app/context.tsx`
- `apps/mobile/app/feedback.tsx`
- focused files under `tests/mobile/**`

Governance/documentation changes are limited to `delivery/**` and `docs/**`.

## Cross-industry and product rules

- Today remains industry-neutral and action-first.
- Recommendation text continues to come from the evidence-qualified Opportunity for the active business.
- No restaurant-specific logic may leak into Atlas Core.
- No Business Pulse, What Changed, Ask Atlas or new Opportunity queue is introduced.
- No fabricated metrics, percentages or business facts are permitted.
- Opportunity Detail remains the source for Why Now, evidence, assumptions, limitations, expiry and Knowledge Pack metadata.
- `Later` remains existing Skip semantics and `Not relevant` remains existing not-relevant semantics.
- Today / History / Goals / Profile route topology remains unchanged.

## Accessibility

- Preserve Dynamic Type behavior and current Reduce Motion/press behavior.
- Keep accessible roles and labels for all actions.
- Do not encode meaning by color alone.
- Preserve minimum touch targets.
- Overflow actions must remain reachable within two taps and accessible to screen readers/keyboard-supported platforms.

## Explicit non-goals

VS-34 does not implement:

- menu/image recovery;
- Bolt/Wolt enrichment expansion;
- Google photo integration;
- connectors or new metrics;
- API or database changes;
- migrations;
- Knowledge Pack changes;
- Pilot Operations;
- production release/deployment;
- Expo harness update;
- EAS build/submit/OTA;
- production database mutation.

## Sequencing

Pilot Operations is paused and reserved to resume later as **VS-35** after VS-34 completes. Menu & Media Coverage Recovery remains a separate later slice.

## TDD and certification policy

Runtime changes must follow verified RED → GREEN cycles. The runtime candidate will be frozen only after focused tests, full mobile validation, authentic Expo Web coverage and exact-head CI / Security baseline / Product Intake succeed. Certification will bind to the exact frozen runtime SHA. Governance-only certification metadata will then receive a second exact-head gate run.

No merge or deployment is authorized by this slice approval alone.
