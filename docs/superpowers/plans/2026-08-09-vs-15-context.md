# VS-15 Context Visual Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate the existing authenticated Business Context screen to the approved Atlas visual system with provenance confirmation, recoverable states, draft-safe retry, accessible save feedback, and no API/navigation/persistence change.

**Architecture:** Keep `apps/mobile/app/(tabs)/context.tsx` as the route and keep `getContext`/`saveContext` as the only server boundary. Add one pure `context-model.ts` beside the other feature models for deterministic merge, provenance, validation, retry/save coordination, and accessibility presentation logic; the route remains responsible for React state and API orchestration.

**Tech Stack:** Expo React Native, TypeScript, Expo Router, existing Atlas API client/session helpers, shared Atlas tokens, Node test runner, PES governance scripts.

## Global Constraints

- Implement FR-05 only.
- Preserve `getContext`, `saveContext`, `loadSession`, `BusinessContextEntry`, authentication, Business isolation, persistence behavior, and the existing five-tab navigation.
- Preserve exact editable API keys: `customers`, `busyPeriods`, `constraints`, `currentPriorities`.
- Preserve unknown API-returned Context entries through merge and save payload construction.
- Do not invent delete semantics; whitespace-only entries remain omitted from the existing save payload.
- Preserve source provenance when editing; public context requires explicit owner confirmation before save.
- Use only `BrandMark` for the temporary prototype mark.
- Use shared `tokens`; no screen-level one-off brand palette.
- Minimum Pressable target: `tokens.touchTarget` (44 points).
- No API/domain/database/migration/auth/navigation/global-state/dependency/release/production change.
- Certification may be claimed only with exact-head evidence required by PES governance.

### Task 3: Migrate the Context route to the Atlas visual system

**Files:**
- Modify: `apps/mobile/app/(tabs)/context.tsx`

**Interfaces:**
- Consumes: existing `getContext`, `saveContext`, `loadSession`, `BrandMark`, `tokens`, and all Task 2 model functions.
- Produces: the same Expo Router screen route and same API calls with improved states/presentation only.

- [ ] **Step 1: Replace implicit initial editing with explicit screen state**

Use:

```ts
type ScreenState = 'loading' | 'ready' | 'missing' | 'error';
```

Initialize `entries` with `createInitialContextEntries()`, use refs for current entries/draft state, and add one Context operation coordinator ref.

- [ ] **Step 2: Implement initial load and manual retry**

Initial load:

```ts
const session = await loadSession();
if (!session?.businessId) {
  setState('missing');
  return;
}
const existing = await getContext(session.accessToken, session.businessId);
setCurrentEntries(mergeContextEntries(existing));
setState('ready');
```

Manual retry must start `refreshing`, call `resolveContextReload`, and preserve a draft when `hasDraftEditsRef.current` is true. Initial failures enter `error`; ready-state retry failures preserve the draft and show the model warning.

- [ ] **Step 3: Implement immutable edit and confirmation handlers**

`update(key, value)` uses `updateContextValue`, sets the draft marker, and clears stale success/validation messages. Public confirmation uses `setContextConfirmation` and also marks the form dirty.

- [ ] **Step 4: Implement serialized Save**

Before network work:

```ts
const validation = getContextValidation(entriesRef.current);
if (validation) {
  setValidation(validation);
  return;
}
```

Then start `saving`, restore the session, and call:

```ts
const saved = await saveContext(
  session.accessToken,
  session.businessId,
  buildContextSavePayload(entriesRef.current)
);
```

Merge the server response with `mergeContextEntries(saved)`, clear the draft marker, and announce `Context saved.` only after success. On failure retain entries and show `Could not save context. Your changes are still here.`.

- [ ] **Step 5: Build loading/missing/error screens**

Use a `ContextState` helper with `BrandMark`, shared tokens, `ActivityIndicator`, `Try again`, and `Choose or create a business` recovery matching the established Profile/Goals geometry.

- [ ] **Step 6: Build the ready-state visual hierarchy**

Use:

```tsx
<BrandMark size={50} />
<Text style={styles.eyebrow}>BUSINESS CONTEXT</Text>
<Text accessibilityRole="header" style={styles.title}>Help Atlas understand how your business works.</Text>
```

Add the minimisation card, four field cards, provenance labels, public confirmation checkbox, feedback region, and full-width deep-green Save action. Content width maxes at 680; outer canvas uses `tokens.color.canvas`.

- [ ] **Step 7: Apply keyboard, small-screen, and accessibility behavior**

The `ScrollView` uses `automaticallyAdjustKeyboardInsets`, `keyboardDismissMode="on-drag"`, and `keyboardShouldPersistTaps="handled"`. Multiline inputs use `textAlignVertical: 'top'`. Confirmation controls and Retry/Save Pressables have at least 44-point targets, semantic roles/state, and busy labels from the model.

- [ ] **Step 8: Run TypeScript/lint/mobile validation**

Run in CI/execution channel:

```bash
npm run mobile:typecheck
npm run mobile:lint
npm run mobile:test
npm run mobile:validate
```

Expected: zero TypeScript/lint failures and all mobile tests green.
