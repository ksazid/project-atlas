## Runtime boundary

The VS-17 verifier is `tests/mobile/progressive-question-runtime.test.mjs`.

It uses deterministic development fixtures only at application boundaries:

- authenticated browser session is supplied through the existing temporary web-session shim;
- a local fixture implements the progressive-question list, answer, skip, and Today boundaries for a selected Business;
- the browser exercises the actual Expo route, mobile API client, model, controls, routing, and session handling;
- every exercised Business request must use `Bearer runtime-token`;
- one answer and one skip are persisted at the fixture boundary;
- an unavailable optional-question service can be bypassed without issuing a fake answer or skip mutation.

The runtime fixture is deliberately deterministic and UI-focused. Category-aware catalogue selection itself is covered independently by `tests/api/ProgressiveQuestionCatalogueTests.cs`, including all eight initial category families plus Generic fallback and the canonical existing `customers` Context key. No LLM/model generates or ranks onboarding questions.

## Category and Context compatibility evidence
